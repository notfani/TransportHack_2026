# Точность и быстродействие

Методика: проигрывание официального bag 1× с `/clock`; подписчик на `/result/*`; эталон — GNSS master velocity (модуль `twist.linear`) с допуском stamp 50 мс. Положение — евклидово XY после проекции GNSS на pathgraph (не кадр автоматической проверки жюри). Записи без GNSS: эталон скорости отсутствует.

Скрипт: `python3 scripts/validate_bag.py <bag> --rate 1 --report reports/run.json`.

В обвязке: если watchdog ушёл вперёд заголовков новых команд, на 1,5 с включается catch-up (шаг `state+1 нс`, якорь receive-clock обновляется). Иначе watchdog «убегает», и оценка расходится. Ядро модели не менялось.

## Быстродействие (`30618_2050d396`, 1×)

| величина | значение |
|---|---|
| частота `/result/velocity` и `/result/position` | 20,09 Гц |
| callback → публикация, max | 4,4 мс |
| CPU средний (одно ядро) / RSS | 12 % / 69 МиБ |
| внутренний max gap | 64 мс |
| внешний max gap положения (подписчик) | 144 мс |

Внешний gap — неравномерность доставки, не измерение «вход→публикация». Сквозная DDS-задержка целиком не закрыта; бюджет 100 мс по callback выдержан. Ресурсы в лимите кейса (≤ 2 ядра, ≤ 0,5 ГБ).
