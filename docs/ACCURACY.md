# Точность и быстродействие

Методика: проигрывание официального bag 1× с `/clock`; подписчик на `/result/*`; эталон — GNSS master velocity (модуль `twist.linear`) с допуском stamp 50 мс. Положение — евклидово XY после проекции GNSS на pathgraph (не кадр автоматической проверки жюри). Записи без GNSS: эталон скорости отсутствует.

Скрипт: `python3 scripts/validate_bag.py <bag> --rate 1 --report reports/run.json`.

## Скорость и путь (ROS, 1×)

| прогон | RMSE v, м/с | MAE v | bias | XY RMSE, м | выходов | Гц |
|---|---:|---:|---:|---:|---:|---:|
| `30618_bab2fe58` (~54 с) | 0,038 | 0,026 | −0,007 | 0,42 | 1142 | 20,02 |
| `30618_2050d396` (~22 мин, путь ≈ 5,35 км) | 0,055 | 0,023 | −0,010 | 5,16 | 26 910 | 20,03 |

На длинном прогоне накопленный путь по оценщику ≈ 5355 м. Гибридная поправка на длинной записи включалась редко (физика из-за устаревшей памяти / вне области); на короткой — в большинстве тактов. Универсальный выигрыш гибрида над таблицей на двух bag не заявлен.

Все выходы конечны, stamp строго возрастает, пары velocity/position совпадают.

## Быстродействие (тот же длинный прогон)

| величина | значение |
|---|---|
| частота `/result/velocity` и `/result/position` | 20,03 Гц |
| callback → две публикации, среднее / max | 0,74 / 8,4 мс |
| тактов с задержкой callback > 100 мс | 0 |
| CPU средний / пик (одно ядро) | 19 % / 56 % |
| RSS | 66 МиБ |
| зазор stamp состояния, p99 / max | 50 / 60 мс |

Наблюдаемый внешним подписчиком max gap положения 123 мс на длинном прогоне — неравномерность доставки, не измерение «вход→публикация». Сквозная задержка DDS целиком не закрыта; бюджет 100 мс по callback выдержан.

Ресурсы укладываются в лимит кейса (≤ 2 ядра, ≤ 0,5 ГБ).
