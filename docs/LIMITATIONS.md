# Ограничения и развитие

## Сейчас не закрыто

- Кадр `pathgraph` не сведён с системой координат автоматической проверки жюри. При расхождении задать `output_x/y/z/yaw` в params.
- Ковариации в `Odometry` — инженерные полы, не калиброванная статистика.
- Гладкий длительный юз обеих тележек одновременно оценщик может принять за движение; раздельный разъезд и короткие всплески отсекаются.
- Гибридная поправка на длинном прогоне почти не включается (память доверенных колёс устаревает). На таких участках работает физика.
- Сквозная задержка «датчик → DDS → подписчик» не равна времени callback; wall-gap подписчика на длинном bag доходил до 144 мс.
- Catch-up 1,5 с публикует метки `state+1 нс` и не чинит сами часы header/receive; если заголовки не догоняют, снова идёт model-only watchdog.
- Адаптация коэффициента тяги в текущем адаптере на контрольных прогонах не уходила с 1.0.
- Температура рельса, загрузка, уклон не наблюдаются тремя входами и не подаются как измерения.

## После хакатона

1. Жёсткое совмещение pathgraph с кадром приёмки (геодезическая привязка антенны к `base_link`).
2. Калибровка ковариаций и порогов юза по отложенным прогонам двух вагонов, без подгонки на сдаточной выборке.
3. Устойчивость к одновременному юзу обеих тележек: дольше держать модель, не возвращать доверие по одному согласному отсчёту.
4. Замер сквозной задержки на целевом железе (два ядра) и выравнивание публикации.
5. Включение адаптации \(k\) только по интервальной невязке, согласованной с тактом колёс.
6. Расширение карты маршрутов без пересборки ноды.
